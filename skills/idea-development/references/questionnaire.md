# Questionnaire

Use when a decision waits on knowledge the user does not have: a domain expert,
a customer, another team. The document is answered asynchronously or walked
through together.

Interview the user only about the send, which they can always answer:

1. **Who receives it?** Their role, expertise and relationship to the user. This
   sets tone and how much context the document must carry.
2. **What must come back?** The specific decisions or facts the user cannot
   settle alone. Every item here needs at least one question.

Then write the questions at the gap between what the recipient knows and what
the user needs. Save it as a Markdown file in the working directory and report
the path.

## Shape

- **Title and purpose:** the decision riding on the answers.
- **From, to, and how answers will be used.**
- **Context:** one paragraph that lets an outsider answer well.
- **How to answer:** deadline, rough effort, and that "unsure" or partial
  answers are welcome.
- **Questions grouped by theme**, most important first, since an async reader
  may give one pass. One idea per question, never compound, each followed by an
  empty answer block. Add a one-line reason only where a question could be
  misread or invite a throwaway answer.
- **Anything else we should have asked?**

Done when the file exists and covers every item from step 2.
